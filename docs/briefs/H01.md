2. `chores`: for each track, extract per project: project id (1E, 1H, …), the status word, and the verify-report path if the README names one. Attached repos: read `README.md` and list `docs/verify/`. Pasted text: use it exactly as given, no interpretation.
3. `chores`: update the twelve Status cells in `README.md`. Allowed words (from the hub README "Status" section): `Planned`, `In progress (<session IDs>)`, `Built`, `Verified`, `Cut`. If a track README uses a different word, copy it verbatim and flag it for the director — do not translate it. Where a verify report exists, link it as `https://github.com/DK1051/<repo>/blob/main/docs/verify/<ID>.md`.
4. Director: cross-check names — the Project column must match each track README's project names character for character; the track README wins on any difference. Update the hub "Status" paragraph with today's date and the list of merged sessions (from the run sheet and Eojin's answers).

8. `wrap`: update `docs/RUN-SHEET.md` (H01 → DONE), `COSTS.md`, `AI-USE.md`, `docs/CAVEATS.md`; push branch `h01-readme-index`; print the PR title and body.
