Repo: takeover-defense · Environment: `takeover-defense`, with all five repos attached · Day: D12 · Time box: 120 minutes · Credit cap: $12

## Goal
Have the `redteam` (Claude Fable 5.1) check every README claim in all five repos against the evidence actually in those repos (verify reports, test output, class transcripts), and turn the result into `docs/FINAL-GATE.md`: one verdict per project — ship / fix first / cut — with concrete fixes. This session edits only the hub repo; fixes in track repos are listed, not made.

## Steps
1. Director (Plan mode): list the five repo paths; for each, inventory `README.md`, project READMEs, `docs/verify/*.md`, `docs/learning/*.md`, `docs/CAVEATS.md`, `COSTS.md`, `AI-USE.md`. Write the **exclusion list** into the plan — paths the `redteam` must never be pointed at because they hold attack content: `td-1-helpdesk/1a-bot-stress-test/cases/`, `td-2-soc/2a-triage/` injection files and `td-2-soc/2h-detection-pack/detections/`, `td-3-iam/3a-agent-passport/cases/`, and any file whose name contains `attack`, `injection` or `payload`. Wait for approval.
2. `redteam`: one call per repo (five calls). Each call names only the allowed paths: the READMEs, verify reports, learning transcripts and CAVEATS of that repo, and tells it in the first line not to open anything else. Ask for its standard output: issues ranked by severity with a concrete fix each, claims to remove or soften (quote the README line), and a verdict per project (ship / fix first / cut).
3. Director: write `docs/FINAL-GATE.md` — a top table `Project | Verdict | Top issue | Fix | Where (repo/path) | Who (Claude session / Eojin)` with exactly twelve rows, then a section per repo with the ranked issues and the claims to soften, quoting the evidence path that supports or contradicts each claim.
4. `chores`: apply the hub-side fixes now — README statuses (`Verified` only where a verify report says PASS on every criterion in scope; `Built`, `Cut` or `In progress` otherwise), and any softened wording in `README.md` and `docs/STORY.md` that the redteam asked for. Track-side fixes are listed in `FINAL-GATE.md` only: this session does not edit the other repos (CLAUDE.md: ask before touching anything outside this repo).
5. Director: the credit-sink plan, as a section `## Credit sink` in `FINAL-GATE.md`. Remaining = Eojin's balance minus a reserve for the fix-first items. Candidate sinks, in this order: (a) fix-first items from the gate; (b) extra evidence runs — 1A with another model or after a fix, 2A with another model, 4A with another model; (c) class sessions not yet held; (d) README polish last. Each item: repo, what, estimated cost, estimated minutes, start-by time in KST so it finishes before Nov 5, 4:00 PM, and who runs it. Total estimated cost must be at or below the remaining balance.
6. `verifier`: check the acceptance criteria; write `docs/verify/H99.md`.
7. `wrap`: update `docs/RUN-SHEET.md` (H99 → DONE), `COSTS.md`, `AI-USE.md`, `docs/CAVEATS.md`; push branch `h99-final-gate`; print the PR title and body.
